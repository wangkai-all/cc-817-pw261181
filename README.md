# 图数据加工服务

从**空目录**搭建的图加工服务：导入带重复来源的虚构边明细，按**群组**统计闭合三角
与**每条边的贡献**，生成可查询的三角事实与节点/边/群组聚集指标。纯 Python 标准库
+ SQLite，无第三方依赖。

## 1. 它解决的问题

1. **业务边与来源条数分离**：同一条边可由多个来源支撑。重复来源不会产生新边、
   新三角；只有撤回**最后一个有效来源**时业务边才被删除。
2. **批次原子性**：一个批次可同时新增/删除多条相邻边。增量以**整批前后两张图做差**，
   而不是逐条顺序输出——逐条顺序会产生批内「临时三角」，正式查询只能看到完整批次结果。
3. **三条边都变化的三角只计一次**：候选三角用集合去重，差集天然不重不漏。
4. **高阶节点代价控制**：定向邻接 + 分区交集，工作单元超预算时回退全量重建，
   结果仍然正确。
5. **节点改群组重建归属**：相关三角的同组/跨组归属与两个群组的指标整体重算，
   不复制旧计数。
6. **守恒与幂等**：每步可跑 8 项守恒核对；全量重建可重复执行且逐行幂等。

## 2. 目录结构

```
graph_service/
  store.py    SQLite 持久层（12 张表，见下）
  graph.py    无状态算法：规范化、定向邻接、分区交集、三角枚举
  engine.py   核心引擎：批次规划/原子提交、增量、回退、迁移、守恒、对比
  samples.py  4 个虚构样例
  loader.py   样例装载
  api.py      标准库 HTTP 服务（JSON API + 写锁 + WAL 快照）
  web/index.html  单页网页（无构建依赖）
  cli.py      命令行
tests/        33 个 unittest
run.py        隔离模式启动脚本   run_tests.py 测试入口
```

## 3. 快速开始

```bash
# 跑全部测试（标准库，-I 隔离环境污染）
python3 -I run_tests.py

# 装载一个样例到全新库，自动输出守恒核对
python3 -I run.py load-sample --db data/demo.db --sample batch_add_remove

# 启动服务与网页
python3 -I run.py serve --db data/graph.db --port 8000
# 浏览器打开 http://127.0.0.1:8000/

# 对现有库跑守恒核对
python3 -I run.py verify --db data/demo.db
```

四个内置样例：

| 样例 | 覆盖点 |
|---|---|
| `star` | 星形图，高阶枢纽 `H` 度 5，无伪三角；定向邻接压力样例 |
| `complete` | K4 完全图（4 三角）+ 跨组 K3（只进全局事实，不进任何群组指标） |
| `duplicate_sources` | 一边两来源、重复导入幂等、逐来源撤回、最后来源撤回才删边 |
| `batch_add_remove` | K4 单批加删相邻边；逐条顺序产生临时三角 `qrs`，正式结果 4→0 |

## 4. 数据模型（SQLite）

- `nodes(node_id, grp)`：节点与群组归属。
- `edges(u,v)` CHECK(u<v)：**业务边**，只有来源袋非空时才存在。
- `edge_sources(u,v,source,batch_id)`：边的多来源，主键含 source，重复来源被自然去重。
- `batches / edge_changes / events`：批次、批内逐条变更（含 `edge_born/edge_died`
  标记）、审计事件。批内顺序仅用于审计，不代表对外可见性。
- `triangles(tid,n1,n2,n3,grp,created_batch)`：三角事实。`tid` 为排序节点的紧凑
  JSON，重复关系无法生成第二个三角。三节点同组 `grp=组名`，否则为哨兵
  `*cross-group*`，**不参与任何群组指标**。
- `edge_tri_support(tid,u,v,sources)`：一条边在一个三角中的**支持记录**，
  保存提交时刻该边的来源快照；这是「查看一个三角的支持记录」的数据源。
- `node_metrics / edge_metrics / group_metrics`：聚集指标。

## 5. 增量算法与倾斜回退

**定向邻接**：按 `(度数, 节点 id)` 给每条无向边唯一定向成 DAG，弧从小秩指向大秩。
每个三角只在其最小秩节点处枚举一次，总工作量 `O(m^1.5)`；高阶节点定向后出度很小，
代价天然受限。

**分区交集**：求 `N(u)∩N(v)` 时以较小邻域为驱动集合分块（chunk），在较大邻域上做
O(1) 哈希探测，避免嵌套扫描，并按探测次数累计工作单元。

**批次增量**：
1. `plan_batch` 在内存模拟来源袋，折叠批内重复，得到受影响边与每条变更的边存亡标记；
2. 在邻接表**独立快照**上构造整批终态图（不逐条改库）；
3. 对每条受影响边分别在旧图、新图求其参与的全部三角，取并集为候选；
4. `新候选 − 旧候选 = 新增`，`旧候选 − 新候选 = 删除`，集合去重保证三边同变只计一次；
5. 单事务提交来源/边/三角/支持/指标，事务成功后才切换内存态。

**倾斜回退**：交集或枚举的工作单元超过 `work_budget` 立即抛 `WorkBudgetExceeded`，
引擎改用**独立的大重建预算**做全量枚举与派生表重写（`mode=full_rebuild`）。
回退预算与触发回退的增量小预算分离，保证回退路径一定能完成；预算恢复后后续批次
自动回到 `incremental` 模式。无论哪种模式，结果都通过同一套守恒核对。

## 6. 守恒核对（`/api/verify`）

1. 业务边存在 ⇔ 来源袋非空；
2. 内存邻接表与 `edges` 表一致；
3. 三角事实 = 全量枚举结果（无幽灵、无缺失、无重复）；
4. 每个三角恰好 3 条支持边且边都存活；
5. 节点度/三角数/聚集系数可重算复现；
6. 边三角支持数可重算复现；
7. 群组 `edge_sum = 3 × triangle_count`，且组三角数与归属表一致；
8. 全局恒等式 `Σ节点三角数 = Σ边支持数 = 3T`。

聚集系数：度 `k<2` 为 0，否则 `3T / C(k,2)`。

## 7. 网页功能

- 左栏**编辑边来源**：动态增删变更行，混合 `add_source/withdraw_source`，
  三个按钮分别为「提交批次」「全量 vs 增量对比（不落库）」「逐条顺序模拟（看临时三角）」；
- **节点改群组**：迁移后展示重判三角数；
- 右栏分页签查看三角事实（点开看支持记录）、边与来源/边贡献、节点聚集指标、
  群组指标（含守恒标记）、批次日志；
- 对比视图**并排**展示增量预测与全量重建预测及一致性结论；
- 顶部一键装载样例、全量重建、运行守恒核对。

## 8. HTTP API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 全量视图（节点/边/三角/三类指标） |
| GET | `/api/triangle/<tid>` | 单个三角的支持记录 |
| GET | `/api/edge/<u>/<v>` | 边来源、贡献、参与的三角 |
| GET | `/api/batches` `/api/verify` `/api/samples` | 日志/守恒/样例 |
| POST | `/api/batch` | 提交来源级批次（原子） |
| POST | `/api/compare` | 全量 vs 增量（dry-run，不落库） |
| POST | `/api/simulate` | 逐条顺序模拟（暴露临时三角） |
| POST | `/api/move-node` | 节点改群组，重建归属 |
| POST | `/api/rebuild` | 全量重建（幂等） |
| POST | `/api/load-sample` | 清空并装载内置样例 |

## 9. 关键正确性约定

- 提交在单事务内完成，WAL 快照下并发查询看不到未提交的批内中间态（已用只读连接验证）。
- 全量重建保留三角的**首次创建批次**（历史事实），因此重复重建逐行幂等。
- 进程重启仅靠持久化表恢复，不重放批次日志。
